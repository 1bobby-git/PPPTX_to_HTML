# 웹 화면 + Native CLI 서비스 · v1.5.0

사용자는 웹 주소에 접속해서 PPTX를 선택하고, 변환 결과를 미리본 뒤 HTML로 저장합니다. CMD 파일을 내려받거나 명령어를 입력하지 않습니다. 이 문서의 설치·실행 단계는 **서비스 운영자용**입니다.

## 실행 구조

브라우저가 같은 주소의 `/api/convert`로 파일과 설정을 전송하면, Node.js 웹 서비스가 `tools/convert-pptx.cjs`를 실행합니다. CLI는 PPTX의 ZIP/XML을 읽어 텍스트·표·이미지·SVG가 들어 있는 독립 HTML을 만듭니다. PowerPoint, LibreOffice, 브라우저 자동화, PDF·슬라이드 전체 PNG 내보내기를 사용하지 않습니다.

웹 서비스가 실행되는 컴퓨터에는 Node.js와 이 저장소의 의존성이 필요합니다. 접속하는 일반 사용자 PC에는 브라우저만 있으면 됩니다. 파일·암호는 접속한 변환 서비스에 전달됩니다. 반환된 HTML은 서버 연결 없이 열 수 있습니다.

**현재 제공하는 것은 실행 가능한 서비스 소스입니다. 저장소에 올린 것만으로 공용 변환 주소가 생기지는 않습니다.** [GitHub Pages는 정적 사이트 호스팅](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)이므로 CLI를 실행할 수 없습니다. 기존 `index.html`은 별도의 브라우저 전용 변환기로 계속 사용할 수 있습니다.

## 운영자가 한 번 준비하기

Node.js 24 계열은 **24.15.0 이상**, 22 계열은 **22.22.2 이상**, 또는 26 이상을 사용합니다. 이 저장소를 준비한 뒤 저장소 폴더에서 실행합니다.

### Windows PowerShell

```powershell
npm.cmd ci --omit=dev --ignore-scripts --no-audit --no-fund
npm.cmd run check:native
npm.cmd start
```

### Linux / macOS

```bash
npm ci --omit=dev --ignore-scripts --no-audit --no-fund
npm run check:native
npm start
```

의존성 설치에는 패키지를 내려받을 수 있는 환경이 필요합니다. 준비가 끝난 뒤 변환 과정에는 외부 변환 API나 CDN이 필요하지 않습니다. 웹 서비스를 실행하기 위해 오프라인 `index.html`을 다시 빌드할 필요도 없습니다.

기본 주소는 **`http://127.0.0.1:3080`**입니다. 이 주소는 서비스를 실행한 컴퓨터에서만 열립니다. 서비스를 종료하면 해당 주소도 작동하지 않습니다. 운영 시에는 조직에서 사용하는 서비스 관리 도구로 Node.js 프로세스를 계속 실행하도록 설정하세요.

## 여러 사용자가 주소 하나로 접속하게 하기

이 구성은 사용자마다 로컬 실행 환경을 설치하는 대신 **운영자가 관리하는 한 서버에서 CLI를 실행**합니다. 사내 서버 또는 조직이 허용한 호스트를 사용하고, 그 서버로 문서가 전달된다는 점을 사용자에게 안내해야 합니다. 이 저장소가 임의의 외부 업체로 문서를 보내지는 않습니다.

### 설정 값

| 환경 변수 | 기본값 | 역할 |
| --- | --- | --- |
| `PPTX_WEB_HOST` | `127.0.0.1` | 웹 서비스가 수신할 인터페이스 |
| `PPTX_WEB_PORT` | `3080` | 수신 포트. 생략하면 호스팅 환경의 `PORT`도 사용 |
| `PPTX_WEB_ORIGIN` | 로컬 접속 주소 | 사용자가 실제로 여는 정확한 `http(s)://호스트[:포트]` |

`PPTX_WEB_ORIGIN`에는 경로·쿼리·사용자 정보가 없는 origin을 지정합니다. 외부 인터페이스로 수신할 때는 이 값이 필수입니다. UI와 API를 동일한 origin의 루트 경로에 둡니다. GitHub Pages 화면에서 별도 API를 호출하는 교차 출처 구성은 지원하지 않습니다.

예를 들어 조직의 HTTPS·로그인 프록시가 `https://slides.example.internal`을 제공한다면, 그 프록시 뒤의 서버에서 다음과 같이 실행합니다. **아래 주소는 설정 예시이며 실제 제공 중인 사이트가 아닙니다.**

```bash
PPTX_WEB_HOST=127.0.0.1 PPTX_WEB_PORT=3080 PPTX_WEB_ORIGIN=https://slides.example.internal npm start
```

프록시는 모든 경로를 `http://127.0.0.1:3080`으로 전달하고, 사용자가 요청한 `Host`를 보존해야 합니다. 서비스는 설정한 origin과 다른 `Host`·`Origin`의 변환 요청을 거부합니다. 외부 주소에 HTTPS를 제공하는 기존 Nginx 서버 블록에서는 다음 location 설정을 사용할 수 있습니다.

```nginx
location / {
    client_max_body_size 65m;
    proxy_pass http://127.0.0.1:3080;
    proxy_set_header Host $http_host;
    proxy_buffer_size 16k;
    proxy_request_buffering off;
    proxy_buffering off;
    proxy_read_timeout 190s;
}
```

이 location 예시는 TLS 인증서나 조직 로그인을 구성하지 않습니다. 서비스 자체에는 사용자 계정 기능이 없으므로, 여러 사람에게 공개할 때는 운영 환경의 접근 제어를 적용하세요. CSRF 토큰은 다른 웹사이트가 임의로 변환을 요청하는 것을 막는 수단이며 로그인 인증을 대신하지 않습니다.

호스팅 환경이 외부 인터페이스 수신을 요구한다면 `PPTX_WEB_HOST=0.0.0.0`과 실제 `PPTX_WEB_ORIGIN`을 명시할 수 있습니다. 이 설정만으로 외부 배포, HTTPS, DNS 또는 로그인 기능이 만들어지지는 않습니다.

## 사용자 화면

화면이 변환 서비스에 연결되면 파일 선택과 변환을 사용할 수 있습니다. 연결이 끊긴 경우 **연결 다시 확인**을 누릅니다. 사용자에게 명령어나 CMD 다운로드 버튼을 제공하지 않습니다.

- 입력: `.pptx` 최대 **64 MiB**. 제목, 원본 슬라이드 범위(`1,3-5`), 숨긴 슬라이드 포함, 지원되는 문서 열기 암호를 설정합니다.
- 변환: 요청당 Native CLI 프로세스 한 개를 실행합니다. 동시 변환은 **한 건**이며, 처리 중 추가 요청에는 다시 시도 안내를 반환합니다.
- 결과: 선택 가능한 텍스트와 리소스를 포함한 HTML 한 파일을 미리보고 저장합니다. 변환 알림이 있으면 결과의 해당 요소를 확인하세요.
- 취소: 진행 중인 HTTP 요청과 해당 요청의 CLI 프로세스를 중단합니다. 이전 요청의 늦은 결과가 새 작업의 화면에 표시되지 않게 처리합니다.

업로드 제한 시간은 60초, 변환 제한 시간은 120초, 결과 전송 제한 시간은 60초입니다. 브라우저는 전체 요청과 응답 수신을 합쳐 195초 후 중단합니다. 큰 파일이나 느린 연결에서 제한에 도달하면 파일을 줄이거나 다시 시도하세요.

## 파일과 암호 처리

각 작업은 운영체제 임시 디렉터리의 별도 폴더에서 고정된 `input.pptx`·`output.html` 이름을 사용합니다. 사용자가 보낸 파일명이나 제목을 서버 파일 경로로 쓰지 않습니다. 파일 형식, 업로드 크기와 multipart 구조를 검사합니다.

암호는 HTTP 요청 본문으로 전달한 뒤 CLI의 표준 입력으로 넘깁니다. 명령행 인자나 URL에 넣지 않으며, 브라우저 저장소·결과 HTML·응답 오류에 저장하지 않습니다. 브라우저 입력란은 변환을 시작할 때 비웁니다. 프로그램은 문서 본문이나 암호를 로그로 남기지 않습니다.

정상 응답 완료, 처리 실패, 취소, 클라이언트 연결 종료 시 해당 작업의 임시 파일을 지웁니다. 프로세스를 강제로 종료하거나 전원이 끊기면 일반적인 정리 코드가 실행되지 않을 수 있으므로, 운영 환경의 임시 디렉터리 정책을 함께 사용하세요. 파일 삭제는 저장장치의 보안 삭제를 의미하지 않습니다.

반환하는 HTML에는 변환 CLI의 정제 처리와 자체 CSP가 적용됩니다. 미리보기는 별도 sandbox iframe으로 표시합니다. 앱과 API 응답은 `Cache-Control: no-store`를 사용하며, 문서를 외부 변환 API로 전송하지 않습니다. 일반 사용자가 직접 클릭한 문서의 웹 링크는 새 탭에서 열릴 수 있습니다.

## 암호·회사 DRM 제한

지원되는 Office 문서 열기 암호를 입력하면 CLI가 복호화 후 변환합니다. 암호가 없거나 틀리면 해당 입력란으로 안내합니다. 알 수 없는 문서 컨테이너를 확장자 변경으로 단정하지 않습니다.

**웹 화면 뒤에서 CLI를 실행해도 NASCA+SD 등 회사 DRM의 인증·복호화를 대신하지는 않습니다.** 현재 NASCA 전용 연동은 구현되어 있지 않습니다. CLI가 실제로 읽을 수 있는 일반 PPTX 데이터가 있어야 변환할 수 있으며, 보호된 원본을 직접 처리하려면 조직이 허용한 공식 연동이 필요합니다. 이 작업에서 실제 NASCA 문서나 Windows 보안 환경을 검증하지 않았습니다.

차트, SmartArt, OLE 개체, 글꼴과 줄바꿈 등의 표현 한계는 [Native CLI 안내](NATIVE_CLI.md)를 따릅니다.

## 개발 및 API 검증

```bash
npm ci
npm run test:web
npm test
```

`test:web`는 실제 CLI 변환, 암호·컨테이너 오류, 요청 검증, 취소·시간 제한·임시 파일 정리와 브라우저 사용자 흐름을 검사합니다. Playwright Chromium이 필요하며 설치된 실행 파일은 `CHROME_BIN`으로 지정할 수 있습니다.

| 경로 | 동작 |
| --- | --- |
| `GET /` | 웹 UI와 요청용 CSRF 토큰 |
| `GET /api/status` | 실행 버전, local/server 모드, 처리 중 여부·한도·현재 CSRF 토큰 |
| `POST /api/convert` | multipart `file` + JSON 문자열 `options`를 받아 변환 |

변환 요청은 같은 origin과 `X-Pptx-Token` 헤더를 요구합니다. 상태 확인 시 현재 토큰을 갱신하므로 서비스가 재시작되어도 다시 연결 후 사용할 수 있습니다. 성공 응답은 `text/html;charset=utf-8`이며, `X-Pptx-Metadata` 헤더에 슬라이드 수·크기·원본 번호·경고를 UTF-8 JSON의 base64url 형식으로 담습니다. 헤더 크기를 제한하기 위해 알림을 줄일 수 있습니다. 실패 응답은 `{ "ok": false, "code": "...", "error": "안내 문구" }`이며 서버의 임시 파일 경로를 노출하지 않습니다.

이 API는 브라우저 화면과 함께 사용하는 동일 출처 서비스입니다. 교차 출처 API, 사용자 파일 보관함, 작업 이력, 사용자 계정, 외부 서버 배포는 포함하지 않습니다.
